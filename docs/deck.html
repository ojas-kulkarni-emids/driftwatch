Intro

DriftWatch audits dependency bumps against the code you actually wrote.

Dependabot and Renovate can tell you a package changed. driftwatch tells you whether that specific change touches your call sites, with evidence you can review before clicking merge.

The goal is simple: move dependency PRs out of the stale queue without asking engineers to read every changelog by hand.
driftwatch - dependency bump auditor

The gap

A version change is not the same thing as a risk assessment.

UP
Bump urllib3 from 1.26.15 to 2.2.1
The bot compares versions and security databases. It does not inspect your repo.

The reviewer still has to answer the useful question: does this bump touch the way our code uses the library?

Merge blind

The PR is small, the checks are green, and the real compatibility work gets pushed into production risk.

Let it sit

The team avoids the unknown, the CVE remains open, and dependency drift keeps accumulating.

What it returns

A verdict per call site, not a vague thumbs-up for the whole repo.

Location Code Verdict
crypto_utils.py:24 Cipher(algorithms.Blowfish(key), modes.CBC(iv)) AFFECTED
crypto_utils.py:30 Cipher(algorithms.AES(key), modes.CBC(iv)) NOT AFFECTED
1. Read dependencies Find pinned packages from requirements.txt or pyproject.toml.
2. Find usage Run a deterministic AST scan for imports, aliases, clients, and calls.
3. Gather evidence Read release notes, changelog files, and issues when the notes are vague.
4. Explain the call Return AFFECTED, NOT AFFECTED, or UNCLEAR with the code that drove it.

Why the design matters

The repo is scanned locally. The agent only sees the evidence it needs.

01
The full repo never enters model context.Python AST scanning happens locally first. Cost scales with how much one library is used, not with repo size.
02
The tool sequence is not hardcoded.A clear changelog can stop early. Ambiguous call sites trigger more file context. Missing release notes send it to changelog files or issues.
03
The UI shows the reasoning trace live.During the audit, you can watch which tools the Strands agent selected and why the final answer has enough evidence.
04
It avoids over-claiming.When a changelog is unclear, the correct output is UNCLEAR, not fake confidence.
